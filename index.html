저장소 하나에서 갈래를 셋 뽑고, 갈래마다 다른 에이전트를 앉힌 다음, 같은 프롬프트를 동시에 넣고 결과 셋을 견줍니다. 체크한 것과 표에 적은 내용은 이 브라우저에 저장되니 새로고침해도 남습니다.

Before we start준비물 점검

넷 중 하나라도 안 되어 있으면 뒤에서 따라오기 어렵습니다. 지금 확인하고 넘어가세요.

하나쯤 안 되어도 괜찮습니다. 두 대로도 오늘 배울 건 다 배웁니다.

Why three왜 한 대가 아니라 세 대인가

에이전트는 같은 문제를 매번 다르게 풉니다. 한 대만 쓰면 그 답이 맞는지 견줄 대상이 없습니다. 셋을 같은 조건으로 돌려 두면 겹치는 부분은 대체로 맞고, 갈리는 부분이 내가 판단할 곳입니다.

worktree · task-a
내가 고른 A
폴더와 터미널이 따로 논다
worktree · task-b
내가 고른 B
폴더와 터미널이 따로 논다
worktree · task-c
내가 고른 C
폴더와 터미널이 따로 논다

diff 세 개 → 읽고 → 고르고 → 하나만 커밋

한 대만 쓸 때

  • 답이 하나뿐이라 비교가 안 된다
  • 마음에 안 들면 처음부터 다시 시킨다
  • 기다리는 동안 할 일이 없다

세 대를 쓸 때

  • 셋을 견줘서 고른다
  • 셋이 같은 곳을 고쳤으면 믿을 만하다
  • 셋이 갈린 곳이 바로 내가 볼 곳

그런데 셋을 한 폴더에서 돌리면 서로의 수정을 덮어씁니다. 그래서 worktree 가 필요합니다.

The key ideaworktree 부터 알고 가자

한 저장소를 여러 폴더로 동시에 체크아웃하는 git 기능입니다. ORCA 는 이걸 작업 하나의 단위로 씁니다.

terminal
git worktree add ../task-a -b task-a
git worktree list
#   /repo            abc1234 [main]
#   /repo/../task-a  abc1234 [task-a]

브랜치만으로는 왜 안 되나

브랜치를 바꾸면 작업 폴더가 통째로 바뀝니다. 세 에이전트가 같은 폴더를 보면 서로의 수정을 덮어씁니다. worktree 는 폴더 자체가 달라서 안 부딪힙니다.

ORCA 에서 이 명령을 직접 칠 일은 거의 없습니다. + 버튼이 대신 해 줍니다. 그래도 안에서 무슨 일이 벌어지는지는 알고 씁시다.

The task오늘 만들 것 — 스톱워치

HTML 파일 하나짜리 스톱워치입니다. 셋이 같은 걸 만들어 오면 무엇이 어떻게 다른지 한눈에 보입니다.

연습용 저장소가 없다면
mkdir stopwatch-lab && cd stopwatch-lab && git init
git commit --allow-empty -m init

결과가 이러면 성공입니다

기준 결과를 먼저 눌러 보고, 세 에이전트의 결과를 이것과 그리고 서로 견주세요.

기준 스톱워치 열어 보기

눌러서 확인할 세 가지

  • 정지 뒤 다시 시작하면 이어지는가
  • 랩 시각이 화면 표시와 맞는가
  • 초기화가 목록도 지우는가

왜 이 과제인가

  • 준비할 저장소가 거의 없다
  • 결과를 브라우저로 바로 볼 수 있다
  • 셋의 차이가 눈에 보인다
  • 30~100 줄 사이로 끝난다

The prompt셋에게 똑같이 줄 프롬프트

한 글자만 달라도 셋을 나란히 놓고 볼 수 없습니다. 복사 버튼을 써서 세 칸에 그대로 넣으세요.

세 칸에 그대로 붙여 넣기
stopwatch.html 파일 하나를 만들어 줘.

- 화면 가운데에 MM:SS.CC 형식으로 시간 표시
- 시작/정지, 랩, 초기화 버튼 세 개
- 랩을 누르면 그 시각을 아래 목록에 쌓기
- 표시는 10 ms 마다 갱신
- 파일은 stopwatch.html 하나만 만들 것
- 외부 라이브러리를 쓰지 말 것
- setTimeout 누적 대신 실제 경과 시간으로 계산할 것

다 만든 뒤 어떻게 시간을 재는지 세 줄로 설명해 줘.

프롬프트에 넣은 네 가지

  • 무엇을 — 파일 이름과 화면 형식
  • 어디까지 — 버튼 셋과 랩 목록
  • 무엇으로 확인 — 브라우저로 열어서 눌러 보기
  • 하지 말 것 — 파일 추가, 외부 라이브러리, setTimeout 누적

마지막 금지 조항이 핵심

  • 이걸 빼면 셋 다 시간이 밀리는 코드를 내놓는 일이 잦습니다
  • 기준 결과가 performance.now() 로 재는 이유입니다

멍하니 기다리지 말고 셋이 어떻게 다르게 접근하는지 적어 두세요. 뒤에서 비교표에 씁니다.

먼저 끝났으면 옆자리 화면을 보러 가도 좋습니다. 같은 프롬프트인데 셋이 얼마나 다른지, 그게 오늘의 핵심입니다.
